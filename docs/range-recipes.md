# 範囲レシピとマクロ台帳（v0.5）

**本書はv0.5時点の設計・統計・実機結果を記録した歴史資料です。** 「初期対応」「未対応」「今後」や件数は当時の状態で、現行の全機能を示しません。範囲指定の基本形式は内部Recipeとして引き続き使用します。外部AIは [Sample Catalog仕様](sample-request-spec.md) を使用してください。

現行の状態は [機械生成Capability Catalog](../capabilities.json)、実機の段階と集計は新たに生成したmacro catalogの `summary` を参照してください。密着・均等、ルビ、文字装飾、本文罫線、罫線表は後続版で実装されています。詳細入口は [開発者ガイド](developer-guide.md) です。文中のv0.5台帳の件数を現在値として再利用しないでください。

最初の実装単位は、優先度0の文字範囲・位置確認と、優先度1の横幅％・文字サイズ・数値字間です。全体の文書スタイルとは別の `operations` として扱います。

## 実行

```powershell
node bin/ichitaro.mjs plan examples/character-ranges.json
node bin/ichitaro-macro.mjs examples/character-ranges.json runs
node bin/ichitaro-macro.mjs examples/range-boundaries.json runs
```

レシピのルートに `targets`、試料ごとに `operations` を指定します。

```json
{
  "text": "甲乙対象丙丁",
  "targets": [
    {"id":"middle","kind":"text","start":2,"end":4,"expected":"対象"}
  ],
  "samples": [
    {"id":"width-120","settings":{},"operations":[
      {"target":"middle","type":"character","attribute":"scaleX","mode":"set","value":120}
    ]}
  ]
}
```

これは抜粋です。完全なレシピには従来どおり `schemaVersion`、`name`、8項目の `defaults` が必要です。開始位置は0始まり、終了位置は対象に含めない半開区間です。期待文字列が本文の該当部分と一致しなければ実行前に拒否します。同じ文字列が複数あっても出現位置を区別できます。

初期対応は、横書き・改行なし・1～96文字のBMP本文です。タブ・制御文字・サロゲート・結合文字は拒否します。対象は最大16範囲、各試料の操作は最大8段階です。段落・セルの範囲指定は未実装で、受理したようには扱いません。

| attribute | API | 値 | 検証 |
|---|---|---|---|
| `scaleX` | `CharacterAttribute` の横拡大率 | 50～200％ | 対象全文字の数値一致 |
| `size` | `CharacterAttribute` の文字サイズ | 3～500pt | 対象全文字の数値一致 |
| `spacing` | `CharacterSpace` | 単位1: -176.4～176.4mm、単位100: -200～200％ | 対象内の文字間の数値・単位一致 |

`spacing` の設定には `unit: 1` または `100` が必須です。解除は `mode:"clear"` とし、value/unitを指定しません。横幅・サイズの解除はまだありません。同じ範囲に `set → set`、`set → clear`、`set → clear → set` と並べると、変更・解除・再設定の各段階を検証できます。

**数値字間と密着割付は別機能です。** 数値字間は選択内のN文字に対してN−1個の文字間に作用しました。末尾文字の後ろの字間は変更せず、末尾文字もガードとして検査します。1文字だけの字間操作は拒否します。

## 適用と検証の手順

1. 操作前に本文の全文字について、文字列・文字属性・文字情報・GetRange位置情報を取得。
2. `CancelAllRange` → `JumpStart` → `CursorRight` → `RangeMode(1)` → `RangeStart` → `CursorRight` → `RangeEnd` で選択。
3. **GetRangeを先に取得**し、GetStringで期待文字列を照合。GetStringで範囲が解除されるため、適用直前に同じ範囲を再選択。
4. 期待文字列と一致した場合だけ固定の属性マクロを呼ぶ。
5. 各操作後に全文字を取得し、対象内の数値一致と対象外の属性・文字情報の不変を確認。字間の末尾ガードも確認。
6. 保存前と再読込後に、全文字の文字列・属性・フラグ・座標を照合。

実機getterの半角カナキーはNFKCで正規化します。例えば `文字ｻｲｽﾞ` と `文字サイズ` を同じ公開項目として扱います。元のgetter出力はUTF-16LEの証跡にそのまま保存します。

manifestの `requested.targets` / `requested.operations` が対象と手順、`observed.characters` が全文字の読み戻し、`verification.rangeProof` が検証範囲と強さです。途中段階の生データも既存のマクロ結果証跡に含まれ、SHA-256で保護されます。対象誤り・対象外への漏れ・未取得getter・保存後の変化は検証成功にしません。

解除は「有効な数値が初期状態へ戻った」ことを確認します。内部記録が消えたことや、明示指定と継承状態の違いまでは確認していません。中間段階は操作後に観測しますが、その段階を独立に保存した証拠ではありません。保存前／再読込後の証明は最終状態についてです。画像による証明は追加していません。

## 台帳を作る（形式の説明とv0.5時点の集計）

```powershell
node bin/ichitaro-catalog.mjs catalogs/my-catalog --run runs/<run-id>
```

複数runは `--run` を繰り返します。CHMの展開先が違う場合は `--help-dir <T36MACのhtmlディレクトリ>` を指定します。生成は読み取りとレポート作成だけで、一太郎は起動しません。出力先は毎回新しいディレクトリにします。

- `catalog.json`: 英日別名、出典ページとハッシュ、抽出した引数シグネチャ、getter、制限、実装状況、実機の値・単位・操作・manifestハッシュ。
- `index.html`: 優先度別の対応状況表。
- 進捗は `資料確認済み → 実装済み → 実機適用済み → 保存・再読込確認済み` を別フラグで管理。
- 実機段階は、整合性検査済みrunの `rangeProof` に基づいて更新。未実行、失敗、読み戻し不一致では昇格しません。
- 操作は `set/change/clear/reset` を区別。`intermediateStateSaved:false` は中間段階で、独立した保存証跡ではありません。

添付CHMでは3,839ページを1,457の英語正規名にまとめました。`?` 付きダイアログ関数は独立分類です。確認済みの表示専用関数もデータ操作と別集計にしています。旧版互換専用の分類枠は用意していますが、今回確定したものは0件であり、互換関数が存在しないという意味ではありません。未確認の1,176関数を通常のデータ操作として数えません。

タイトルとシグネチャの自動収集は、資料をレビューしたという意味ではありません。実装済み4能力の引数範囲も、実機で全値域を確認した意味ではありません。台帳は実証した値と範囲を列挙し、関数を呼べた数だけで網羅率を出しません。現在の進捗の分母は優先度0～7の14能力で、以前からある文書スタイル機能とは別集計です。

文字囲み・文字装飾・段落飾り・本文罫線・罫線表は独立した能力IDです。今後は優先度2の密着・均等割付、3のルビへ進めます。均等割付の存在だけを返すgetterで、幅まで検証済みとしない設計を維持します。

## 観測機能との接続

```powershell
node bin/ichitaro-observe.mjs run runs/<run-id>
```

文字ごとの読み戻しもバイト差分との対応候補に含まれます。候補から生成される次のレシピには対象範囲を引き継ぎます。ただし文字属性getterは現在文字列値として保存するため、文字属性の新しい数値候補を自動生成する機能は未対応です。範囲を持つ対照試料は生成できます。

## 2026-10-14 順次読み戻しと長い本文

範囲属性の読み戻しを、1文字ごとに「文書先頭から移動し、1文字を範囲選択する」方式から、段落ごとに1回だけ先頭へ移動し `CursorRight(1)` で順に進む方式へ変えた。照合する内容（全文字、全文字属性・文字情報・ルビ、各段階、保存前・再読込後）は減らしていない。

### 計測（[計測スクリプト](../tmp/profile-readback.mjs)、[順次版](../tmp/profile-readback-v2.mjs)）

100文字分を処理ごとに繰り返し、マクロ全体の時間から固定費を引いた1文字あたりの時間は次のとおりだった。

| 処理 | 1文字あたり |
|---|---|
| 文書先頭からの移動（`CancelAllRange`・`JumpStart`・`NextParagraph`・`CursorRight(k)`） | 約33ms |
| 1文字の範囲選択と解除 | 約27ms（`GetRange`・`GetString` 込みで約36ms） |
| 全getter（文字属性・文字情報・密着／均等・ルビ・文字） | 約3ms |
| 位置のgetter（`GetPage`・`GetRow`・`GetColumn`・`GetPosition`） | 約1ms |
| 順に1文字進む `CursorRight(1)` | 約1ms |

ドラフト編集画面への切替は約1割の短縮にとどまった。

### 範囲選択を使わない読み方の同等性

- [プローブ](../tmp/probe-cursor-paragraphs-v1.mjs)：`CursorRight` は行の折り返しをまたぐが、段落末（文字種10）を越えて次の段落へは進まず、同じ行の空白領域（文字種0）を右へ進む。そのため各段落へは `NextParagraph` で移動する。最後の段落の末尾は文字種10ではなく文書末である。
- [プローブ](../tmp/probe-cursor-ruby-v1.mjs)：ルビや均等割付の後の空のカーソル位置で、1文字選択の `GetString` は空、`GetCharacter()` は空で文字種0だった。各文字の `GetCharacter()` は選択の `GetString` と、`GetPage`・`GetRow`・`GetColumn` は `GetRange` の始点と一致した。
- 範囲属性の全Recipeで保存された82試料・833文字について、同じJTDを旧方式（[保存した旧実装](../tmp/ranges-legacy-20261014.mjs)）と新方式の両方で読み戻し（[突き合わせツール](../tmp/compare-readback.mjs)）、文字・全属性・文字情報・ルビ・始点座標の差は0件だった。新方式はルビが最後の文字にある場合の末尾の空の位置も記録する。旧方式の終点座標は、空の位置を挟む場合と行の折り返し位置では次の位置の始点と一致しないため記録しない。突き合わせの結果は[展開版](../tmp/compare-readback-20261014.json)と、走査をループにした最終版（[結果](../tmp/compare-readback-loop-20261014.json)）の両方で差分0件。最終版で範囲属性の内部Recipe9種と公開例03・04・07・08・13を再実行し、すべて以前と同じくverifiedだった（[一覧](../tmp/regression-sequential-loop-20261014.json)）。

### ずれを合格にしないための照合

- 空の位置の読み飛ばしは、文字、段落末（文字種10）、文書末の座標（各段階の最初に `JumpEnd` で記録）のいずれかで止まる。
- 各段落の最後の文字の次は、途中の段落なら段落末、最後の段落なら文書末でなければならない（余分な文字や走査のずれを不合格にする）。最初の実行では文書末の判定がなく、最後の段落で読み飛ばしが空白領域を進み、段階間の座標の不一致として検出された（合格にはならなかった）。
- 各操作では対象の先頭まで移動した位置の座標が直前の読み戻しと一致すること、選択した文字列が期待どおりであることを確認する。
- 用紙上のX・Y（mm）は新しい情報なので記録のみで、照合には使っていない。

### 長い本文

公開の本文は最大2000字、LFで区切った空でない段落を使える。範囲は1つの段落の中に置く。注釈のない複数段落の本文も1文字ずつの読み戻しで段落構造を確認する（横書きのみ）。

段落内の走査はマクロのループにした。1文字ごとにマクロを展開すると約2000字で9MBになり、一太郎はそのマクロを開始しなかった（結果ファイルも作られず、新しいプロセスもなかった）。ループ版では約150KBである。

1999字・10段落の本文（下線・均等割付・ルビ）で、ベースライン（3段階）28秒、要求試料（6段階）53秒でverifiedだった（[run](../runs/2026-10-14T14-54-30-272Z-d8913d56/index.html)）。1段階あたり約9秒、1文字あたり約4.5ms。結果ファイルは14MB・29MBになる。タイムアウトは「20秒＋文字数×段階数×10ms」で見積もり、下限は既定の120秒、上限は300秒とした。

[公開例](../examples/agent/26-long-text.json)の3要求（段落ごとのルビと下線、1500字の終盤の文字サイズ、注釈のない4段落と文書スタイル）が実機でverified（[結果](../tmp/public-long-text-20261014/execution-results.json)）。

### X・Y座標を照合に切り替える条件

用紙上のX・Y（`GetPosition(1)`、mm）は2026-10-14から記録のみ。次の条件をすべて満たしたら照合に切り替える。判定は `node scripts/geometry-stability.mjs`（実験ストレージを読む）で行う。

1. 記録した試料が200以上あり、保存前と再読込後でX・Yが変わった試料が0件。
2. 属性の種類が6種類以上（ルビ・均等割付・文字サイズ・書体など、配置を動かす操作を含む）。
3. 同じRecipe・同じ試料を別のrunで3組以上作り、保存前のX・Yがすべて一致する（再現性）。
4. 記録が2日以上にわたる（同じ日・同じ一太郎の起動状態だけに依存しない）。
5. 2ページ目以降の文字を含む記録がある。

切り替え後も照合するのは「最後の操作の後→保存前→再読込後」の不変性だけで、操作による変化（文字サイズ変更で後続の文字が動くなど）は対象外とする。縦書きのX・Yの意味は未確認なので、縦書き対応時に別途確認する。2026-10-14時点では条件1〜3を満たし（252試料・10348文字、変化0件、13種類、繰り返し114組で差0件）、4と5が未達。

### 継続課題

- **縦書きの複数段落の本文**：1文字ずつの読み戻しは横書き専用で、縦書きで段落区切りを含む本文や範囲注釈は拒否している。縦書きでの `CursorRight`／`NextParagraph` の進み方、段落末・文書末の判定、座標getterの意味をプローブで確かめて対応する（今回の改修の続きとして扱う）。

## 2026-10-15 太字・斜体・文字色・範囲ごとの書体

[プローブ](../tmp/probe-character-styles-v1.mjs)で、`Bold()` と `Font(,"太字")` はどちらも `GetCharacterAttribute` の和文スタイル名を「太字」にした。`Font(,"斜体")` は「斜体」、`CharacterAttribute` の文字色は「文字色」、`Font("游ゴシック")` は和文フォント名に反映し、いずれも保存・再読込後も保持された。[2回目](../tmp/probe-character-styles-v2.mjs)で `Font(,"太字斜体")` は無視され「標準」のままだったため、太字と斜体の同時指定は扱わない。

範囲属性 `fontStyle`（標準・太字・斜体）、`textColor`、`fontName` を追加し、公開注釈 `character-font-style`・`character-color`・`character-font` とした。指定した属性の値を厳密に照合し、範囲内の他の全属性・文字情報・ルビと範囲外の全文字が変わらないことを確認する。インストールされていない書体名は反映されず読み戻しで失敗する。[公開例](../examples/agent/27-character-style.json)の5要求（太字、斜体、文字色、書体、4種類の混在）が実機でverified（[結果](../tmp/public-character-style-20261015/execution-results.json)）。
