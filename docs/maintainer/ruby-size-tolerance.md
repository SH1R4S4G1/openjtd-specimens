# ルビの大きさ（sizeMm）の読み戻し許容差

2026-10-11 に、第9回試料（rb9-l-s3p9-n2）の作成が、読み戻しの照合不一致で止まったことから導入しました。

## 現象

`Ruby(...)` でルビの大きさ（サイズ、mm）を設定した直後に `GetRubyDecoration` で読み戻すと、一太郎が要求値より 0.01mm 小さい値を返す場合があります。

- 要求より 0.01 小さく返った値: 3.3→3.29、3.4→3.39、3.8→3.79、3.9→3.89、4.1→4.09、4.3→4.29、4.6→4.59、4.8→4.79
- 要求どおり返った値: 3、3.1、3.2、3.5、3.6、3.7、4、4.2、4.4、4.5、4.7、4.9、5、5.5、6、7、8、9、10
- 3.89 は設定直後に決まり、保存前・保存後・再読込で変わりません（保存でずれたのではありません）。
- 規則は特定できていません。単位換算の切り捨てに見えますが、0.01mm 単位の切り捨てでは説明できませんでした。ヘルプ（Ruby / SetRuby）に丸めの記述はありません。
- 実機試験の記録（別セッション）: そのセッションの一時フォルダの `probe-out\result.txt`（リポジトリには含まない）

## 対応

`src/ranges.mjs` のルビ照合で、`sizeMm` に限り 0.02mm 以内の差を一致として扱います（`RUBY_SIZE_TOLERANCE_MM`）。

- 今回の検証の目的は「JTD が正しく作られたか」の確認であり、一太郎が実機で返す値を許容します。誤差の理由の調査は別途行います。
- 差が 0.02mm を超えれば、従来どおり不一致（失敗）です。他の項目（距離・位置・上下・読み・均等割付など）は完全一致のままです。
- 許容した場合、各文字の要求値・実際の値・差を `manifest.json` の `verification.rangeProof.checks[].sizeMmTolerance.observations` に記録します。`limitations` にも説明を追加しています。
- 要求（`expected`）の値は変更しません。実際に保存された値は 3.89 などです。OpenJTD 側の解析では、この差に注意してください。

## 影響を受けた試料

- 第9回（r9）: rb9-l-s3p9-n2 / n3 / n4（3.9mm）。ほかは、作成後に `sizeMmTolerance` の記録がある試料を確認してください。
