# JTDの差分観測（v0.4）

一太郎を起動せず、保存済みJTDとgetter証跡から「変更位置・バイト列・設定との対応候補」を計算します。出力は元のrunと分離し、元JTD・manifestを書き換えません。既存の出力先への上書きも拒否します。

## エージェント向けの入口

```powershell
node bin/ichitaro-observe.mjs run runs/<run-id>
```

標準出力は短いJSONです。比較基準、候補領域数、反復内変動、候補上位12件のストリーム・位置・バイト値・連動した観測項目、詳細ファイルと次のレシピへのパスを返します。全ファイルのhex dumpを会話に貼り付ける必要はありません。

出力先と比較基準を指定する場合：

```powershell
node bin/ichitaro-observe.mjs run runs/<run-id> observations/my-analysis baseline
```

出力先省略時は `observations/<時刻とID>/` を作成します。run観測では入力の整合性検査を行い、全試料が `verified` の場合だけ設定との対応候補を計算します。入力と出力は別ディレクトリにしてください。

| 出力 | 内容 |
|---|---|
| `summary.json` | エージェント向け要約 |
| `observation.json` | 全入力のSHA-256・manifestハッシュ、要求値・観測値、比較一覧、候補と除外理由、反復内で変動した領域の位置とhex |
| `pairs/<sample-id>.json` | 比較基準から各試料への物理差分、ストリーム差分、前後のhexと物理位置 |
| `index.html` | 人が確認する一覧とバイト列 |
| `next-probes.json` | 対照2件と未試験値を指定した次のレシピ。**自動実行しません** |

## 差分位置の意味

CFB形式のファイルは公開コンテナ構造だけを読みます。文書の意味やJTD独自のフィールド構造は解読しません。

- **物理差分**：ファイル先頭からの0始まりオフセット。同じ位置のバイトを比較。
- **論理差分**：ストレージ階層とストリーム名が同じデータ同士を比較。コンテナ内のセクター再配置を吸収。
- **物理位置への対応**：各論理変更範囲に `beforePhysical` / `afterPhysical` を付け、元ファイルの位置へ戻せるようにする。セクター境界をまたぐ場合は複数範囲。

連続する変更を一つの範囲にまとめ、先頭32バイトのhex、全変更範囲のSHA-256、長さを記録します。比較ごとの各差分は最大4,096範囲まで保存し、それを超える範囲数も記録します。オフセットは10進数と16進数を併記します。挿入・削除位置の推測や、圧縮データの解凍は行いません。長さが変化したストリームには位置ずれが含まれ得ます。

必要なバイトだけを取得する例（PowerShell）：

```powershell
node bin/ichitaro-observe.mjs slice runs/<run-id>/samples/<id>/document.jtd 0x21 16 '["PageMark"]'
node bin/ichitaro-observe.mjs slice runs/<run-id>/samples/<id>/document.jtd 0x800 64
```

末尾のJSON配列はストリームへの階層パスです。省略時はファイル全体の物理位置を指定します。`slice` は1～4,096バイトを省略なしのhexと物理位置で返し、入力ファイルのSHA-256も付けます。

未完了runや任意の2ファイルは、設定との対応付けをせず比較できます。

```powershell
node bin/ichitaro-observe.mjs pair before.jtd after.jtd observations/manual-pair
```

この経路では元の設定証跡を検証していないことを明示します。CFB以外は物理差分だけを出し、CFBの破損・未対応構造はエラーにします。

## 対応候補の選び方

1. `fullName` を除く記録済みgetterと本文が基準試料と等しい再保存試料を探す。`control-*` を優先して比較基準にする。なければbaselineを使う。選択理由を記録する。
2. 再保存試料を基準にした場合、初回保存のbaselineを対応候補の計算から外す。baselineとの比較自体は差分ファイルに残す。初回保存と再保存ではストリームが増える実例があるため。
3. 候補計算の対象全試料に存在し、長さも同じストリームの同じ位置だけを調べる。長さが違うストリームの差分は記録するが、対応候補にはしない。
4. 記録された観測値・本文が同じ試料群で値が変動するバイト位置を除外する。日時等とは断定せず「反復内で変動した位置」と呼ぶ。
5. ある観測項目の値が同じ試料群ではバイトも同じで、値の変化に伴ってバイトが変わる位置を対応候補にする。隣接位置で候補項目が一致すれば最大32バイトの領域にまとめる。

これは観測上の対応であり、原因やエンコード方式の証明ではありません。連動する余白・行間なども候補項目に残します。反復群がゼロなら再現性は未確認です。「対照では変わらなかった」ことだけでも設定フィールドとは断定できません。記録外の環境や保存操作が原因の可能性も残ります。

対応候補と反復内変動の詳細はそれぞれ最大256領域、評価する変更位置は最大200,000位置で、省略数を出します。runは2～200試料、JTD単体は16 MiB、合計は128 MiBまでです。上限に達した結果を全体の網羅的な解読結果と扱わないでください。

次のレシピは、候補に現れる変更可能な数値項目から未試験値を最大5項目選び、一項目ずつ指定します。既存のレシピ検証器を通しますが、一太郎での受理・値の維持までは保証しません。新しいbaselineのフォント・用紙等は環境設定を継承するため、前runの観測値との比較も必要です。数値候補がない場合は対照試料のみを提案します。

## 実データでの確認

フォントの2軸×2反復を含む11試料（`2026-10-09T17-25-03-918Z-ffc6a8b0`）では、`control-r1` が比較基準になりました。反復内で変動した12位置を除外し、`PageMark` の `0x21`, `0x27`, `0x29`, `0x2f`, `0x31`, `0x33` に6つの1バイト候補を検出しました。文字サイズ、行間、左右余白が連動するため、候補はそれらを併記します。`DocumentViewStyles` は長さが変化するため候補計算から除外しました。

対照を含まない拡張設定11試料（`2026-10-09T17-24-09-524Z-a5704045`）では、長さ等による15ストリームの除外後、候補は0件でした。差分がないという意味ではありません。物理・ストリーム差分は別途残っています。

## 公開仕様とクリーンな観測

CFBの読み取りはMicrosoft公開仕様の[ヘッダー](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/05060311-bfce-4b12-874d-71fd4ce63aea)、[構造](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/28488197-8193-49d7-84d8-dfd692418ccd)、[ディレクトリ](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/a94d7445-c4be-49cd-b6b9-2f4abc663817)、[Mini FAT](https://learn.microsoft.com/en-us/openspecs/windows_protocols/ms-cfb/c5d235f7-b73c-4ec5-bf8d-5c08306cd023)に基づきます。JTD独自の意味を第三者実装から取り込まず、正規品が保存したファイルの観測に限定しています。DLL解析・JTD書き換えは行いません。CFBリーダーは完全な適合性検査器ではありませんが、範囲外参照・循環・重複割当・ディレクトリ異常を検出して停止します。
