# 禁則・ジャスティフィケーションの設定（APP-11）

文書スタイルの体裁は `DocumentStyleRoman`（設定、公式ヘルプ t26m338u）と `GetDocumentStyleRoman`（取得、t26m4qlq）で扱う。内部の機能グループ `typesetting` は設定引数の順に20項目を持ち、`captureFeatures` を使う全試料で20項目すべてを保存前と再読込後に記録・比較する。8番目の取得キーは公式ヘルプの表記どおり半角カナの `半角括弧類を和文ﾌｫﾝﾄにする` で読める。

## 外部要求

Sample Catalogの `text` / `paragraphs` 文書に `typesetting` を指定する。公開する項目は次の7つ。値は1回の `DocumentStyleRoman` 呼出しにまとめて渡し、指定した値を保存前に照合する。

| 項目 | 一太郎の項目 | 値 |
|---|---|---|
| `justification` | ジャスティフィケーション | true→1（必ず行末まで揃える）、false→0 |
| `kinsoku` | 禁則処理 | true→1、false→0 |
| `lineStartForbidden` / `lineEndForbidden` | 行頭・行末禁則文字 | 文字列全体の置換 |
| `hanging` | ぶら下げ | true→1、false→0 |
| `pushIn` | 追い込み | true→1、false→0 |
| `bracketOverlap` | 括弧類の重なり処理 | true→1、false→0 |

[完成例](../examples/agent/30-typesetting.json)は、`text` 文書で1項目ずつ変えた7試料と、`paragraphs` 文書の2試料からなる。全試料が保存前・再読込後の照合を通過した。

## 実機で確認した制約（2026-10-15、一太郎2026）

一度に1項目ずつ新規文書へ設定し、保存・再読込して確認した。

- ジャスティフィケーションの2（標準的な見栄えまで広げる）は「引数の値が不適切です」で拒否される。外部要求は真偽値の0/1だけを受け付ける。
- 禁則処理を0にすると、ぶら下げ・追い込み・括弧類の重なり処理が0になる。禁則処理falseとこれらのtrueを同時に要求すると拒否する。
- 既定（追い込み1）のままぶら下げ1、括弧類の重なり処理0を設定すると拒否される。同じ呼出しで追い込み0を渡すと設定できるため、外部要求では `pushIn: false` の明示を必須とした。値をコンパイラが補うことはしない。
- 字間の広げ方は、0を渡しても1のまま、別の状態では1を渡して0が返った。設定値が反映されないため未公開とし、記録だけを行う。
- 行頭・行末禁則文字は指定した文字列がそのまま返り、再読込後も保持された。

検証するのは文書スタイルの保存値で、実際の改行位置・ぶら下がり・詰めの結果は測っていない。約物の詰め（プロポーショナル）に相当する引数は `DocumentStyleRoman` にない。欧文の体裁、ベース位置、行頭シフトなど残りの項目は内部Recipeで記録・比較するだけで、外部要求には公開していない。

## paragraphs文書での確認（2026-10-15）

公開時に実機で通したのは `text` 文書だけだった。`paragraphs` 文書で確かめたところ、段落書式だけの文書は通ったが、ヘッダー・段組・枠などの構造要素を含む文書では、コンパイル時の共通基準の上書き許可に `typesetting` がなく拒否されていた（Schemaは受け付けていた）。上書き許可に加え、ページ番号と同じく共通基準へ重ねるよう修正した。

- [paragraphs-kinsoku-off](../runs/2026-10-15T12-41-50-293Z-cb4be39b/index.html): 段落書式と併用し禁則処理を0にした。ぶら下げ・追い込み・括弧類の重なり処理も0になり、保存前・再読込後で一致した。
- [combination-hanging](../runs/2026-10-15T12-42-02-723Z-7663f61e/index.html): ヘッダー・2段組・段落書式・枠と併用し、ジャスティフィケーション0、ぶら下げ1（追い込み0）、行頭禁則文字の置換を設定した。体裁の値に加え、ヘッダー・段組・枠・段落の各読み戻しも通過した。
