# 機能の組合せ

2026-10-14に、構造要素どうしと、構造要素と文書条件（フォント・用紙・文書スタイル）の組合せを実行層と外部要求APIで解禁しました。許可する組合せは実機で検証したものに限り、[experiment.mjs](../src/experiment.mjs) の組合せ表とコンパイラで明示しています。

## 許可している組合せ

| 要素 | 組み合わせられる要素 |
|---|---|
| ヘッダー／フッター（1ページ） | 段組、段落属性、枠、脚注 |
| 段組 | ヘッダー／フッター、段落属性、枠 |
| 段落属性 | ヘッダー／フッター、段組、枠 |
| 枠 | ヘッダー／フッター、段組、段落属性 |
| 脚注 | ヘッダー／フッター（1ページ）のみ |
| 名前付きスタイル | なし（単独試験） |
| 3ページのヘッダー／フッター | なし（単独試験） |

構造要素を含む文書は、横書き・A4縦・游明朝10.5ptの基準から始め、フォント（名前・サイズ）と用紙を上書きできます。文書スタイル（字数・行数・字間・行間・余白）も指定できます。段組書式・ページ番号・体裁（[禁則・ジャスティフィケーション](typesetting.md)）も上書きできます。縦書きとの組合せ、文字範囲の属性（範囲注釈）や罫線表との組合せは未対応です。

外部要求では `paragraphs` 文書に複数の要素を同時に書きます。[公開例](../examples/agent/19-combinations.json)を参照してください。

## 組合せのために変更した検証

- マクロは全要素を適用してから、全要素の保存前の読み戻しを行う順にしました。後の要素の適用で先の要素の状態が変わった場合も、保存前と再読込後に検出できます。単独の試料では呼出順は変わりません。
- ヘッダー／フッターの本文照合は、脚注がある場合に脚注番号入りの本文を期待値にします。
- 段組は本文の `GetString` に構造上の空行を、枠は余分な空白を加えます。両要素とも本文を1文字ずつ `GetCharacter` で照合しているので、組み合わせた他の要素の `GetString` 比較では、その空行・空白だけを無視します。文字の同一性の照合は緩めていません。

## 脚注エリアの表示ラベル

脚注本文の先頭には一太郎が表示ラベルを付けます。10/13の検証では、挿入直後に取得したラベル（「*1」）がそのまま残りました。2026-10-14の実行では、単独の脚注試料も含めて、本文順の番号（「1」「2」）で表示されるようになりました。表示形式を切り替えた原因（アプリケーション側のどの状態か）は特定できていません。余白表示をオフにしても変わりませんでした。

番号形式で表示される場合、前の脚注を削除しても、残った脚注のラベルは更新されず、それまでに付いた番号のまま残ります（本文側の番号は振り直されます）。これは[脚注の調査記録](footnotes.md)にある「表示接頭辞は3のまま保持された」と同じ挙動です。

脚注の所属は本文の番号と脚注本文の往復ジャンプで証明しています。そのため脚注本文の照合では、ラベルが次のいずれかで、続く内容が要求文字列と完全に一致することを求めます。

- 挿入直後に取得したラベル（`captured`）
- 現在の本文順の番号（`number`）
- その段階までにその脚注が取ったことのある本文順の番号（`earlier-number`）。どの番号を取ったかは要求の履歴から機械的に求め、それ以外の番号は拒否します。

どの形式だったかは `prefixForm` として証跡に記録します。ラベルの形式は所属の証明には使いません。

## スタイル登録名一覧

同じ日に、名前付きスタイルの試験でも、baselineのJTDを開いた直後の登録名一覧に「脚注(標準)」「脚注ｴﾘｱ(標準)」が現れるようになりました（10/12は空）。新規文書とその再読込では今日も0件です。一太郎は一覧を名前順で返すため、追加した名前の位置が変わり、順序込みの比較が不一致になりました（[停止run](../runs/2026-10-14T11-57-14-361Z-d90d8473/index.html)）。一覧の照合は、並び順を無視して「登録前の一覧＋追加した名前」と件数・内容が一致することを求める形に改めました。脚注ラベルの変化と同様、アプリケーション側の状態変化の原因は特定できていません。
